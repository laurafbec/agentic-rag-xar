# Kafka environment for accountability
Docker-based Kafka environment for the accountability and explainability architecture of autonomous robots.

This component provides the Kafka infrastructure used to receive ROS 2 messages and forward them to MongoDB Atlas, where the messages can be stored and enriched with vector embeddings for subsequent retrieval.

 ## System requirements
 The environment requires:

- Docker
- Docker Compose
- A host system where the Kafka broker can be reached by the ROS 2 and Kafka clients.

The hostname `broker1` must be resolvable to the IP address of the machine running Kafka. This can be achieved by adding an entry to the `/etc/hosts` file if DNS resolution is not available.

For example:

```text
<HOST_IP> broker1
```
 
 Host IP must be set in the Docker environment variable ```BROKER_KAFKA_ADVERTISED_HOST_NAME```, defined in [.env](https://github.com/laurafbec/agentic-rag-xar/blob/main/accountability-kafka-docker/.env#L13).

 ## TLS configuration
To enable TLS support, self-signed certificates, keystores and truststores can be generated by running the script [create-secrets.sh](https://github.com/laurafbec/agentic-rag-xar/blob/main/accountability-kafka-docker/secrets/create-secrets.sh).

The generated security files are used by the Kafka and Kafka Connect services.

## MongoDB Atlas configuration

MongoDB connection URI value must be assigned to the connection.uri property in [MongoSinkConnector.properties](https://github.com/laurafbec/agentic-rag-xar/blob/main/accountability-kafka-docker/mongodb-kafka-connect/etc/MongoSinkConnector.properties) from Kafka connect, and in [sink-connect.sh](https://github.com/laurafbec/agentic-rag-xar/blob/main/accountability-kafka-docker/kafka/scripts/sink-connect.sh) for the Kafka-MongoDB connector creation. 
Replace the placeholder credentials and cluster information with the connection details of the MongoDB Atlas deployment.
For example:
```
mongodb+srv://user:password@cluster0.ecipx.mongodb_uri.net/admin?ssl=true
```

## Deployment

The environment can be deployed by running
```
docker-compose -f docker-compose-tls-atlas-vector.yml up
```
To start the environment in detached mode:
```
docker-compose -f docker-compose-tls-atlas-vector.yml up -d
```
To stop the environment:
```
docker-compose -f docker-compose-tls-atlas-vector.yml down
```
## Kafka topic
The ROS 2 messages are published to the following Kafka topic ```ROSMessagesTopic```.

Kafka Connect consumes messages from this topic and stores them in MongoDB Atlas.

```
docker ps -a
```

```broker1``` for the Kafka broker
```connect``` for Kafka Connect
```zookeeper``` for Apache Zookeeper

Kafka broker logs can be inspected with:
```

docker logs connect
```

## ROS 2 messages
The messages stored in Kafka originate from the ROS 2 environment used by the accountability architecture.

A typical document stored in MongoDB Atlas contains the ROS 2 topic together with the textual representation of the corresponding message.
```
{
  "goal_id": "unique_identifier_msgs.msg.UUID(...)",
  "goal_number": 1,
  "topic_name": "navigate_to_pose/_action/status",
  "log_message": "1739992463.762627821 Navigation to the goal number 1 is in progress."
}
```
The ```log_message``` field contains the textual information that is used to generate the vector embedding.

## MongoDB Atlas embeddings
After a document is stored in MongoDB Atlas, an Atlas Trigger generates an embedding for the ```log_message``` field using the configured embedding service.

The resulting embedding is stored in the ```log_message_embedding``` field.

After embedding generation, the document has the following structure:
```
{
  "goal_id": "unique_identifier_msgs.msg.UUID(...)",
  "goal_number": 1,
  "topic_name": "navigate_to_pose/_action/status",
  "log_message": "1739992463.762627821 Navigation to the goal number 1 is in progress.",
  "log_message_embedding": [
    "...",
    "...",
    "..."
  ]
}
```
The embedding generation is performed by the MongoDB Atlas Trigger and is not part of the Kafka message itself.

## Data flow

The overall data flow provided by this component is:

```text
ROS 2
  |
  v
Kafka
  |
  | ROSMessagesTopic
  v
Kafka Connect
  |
  v
MongoDB Atlas
  |
  | Atlas Trigger
  v
log_message_embedding
```

This component provides the messaging and persistence infrastructure required to transfer ROS 2 information from the robotic environment to MongoDB Atlas, where the resulting documents can be indexed and retrieved by the explainability components.
