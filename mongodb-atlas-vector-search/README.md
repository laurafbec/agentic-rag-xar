# MongoDB Atlas Vector Search Configuration

The software uses **MongoDB Atlas** to store ROS 2 messages and their corresponding vector embeddings.

The retrieval component follows a hybrid search strategy that combines:

- lexical retrieval using **MongoDB Atlas Search (BM25)**;
- semantic retrieval using **MongoDB Atlas Vector Search**; and
- **Reciprocal Rank Fusion (RRF)** to combine the results obtained from both retrieval mechanisms.

This document summarizes the MongoDB Atlas configuration required to run the software.


## Requirements

A MongoDB Atlas account is required.

The experiments were conducted using an **M0 free-tier cluster running MongoDB 8.0.6**.

The following components must be configured:

1. MongoDB Atlas cluster.
2. Database user.
3. Network access.
4. Database and collection.
5. Atlas Search index.
6. Atlas Vector Search index.
7. API credentials for the selected embedding service.
8. MongoDB Atlas Trigger for automatic embedding generation.

## Database configuration

Create a MongoDB Atlas database user with the required username, password, and database access privileges. Network access must also be enabled for the machine from which the application connects to MongoDB Atlas.

Create the database and collection used by the application. The collection stores the ROS 2 messages together with their corresponding vector embeddings.

The MongoDB connection string follows the format:

```text
mongodb+srv://<username>:<db_password>@cluster0.XXXXXX.mongodb.net/
```

Replace `<username>` and `<db_password>` with the credentials of the database user.

The retrieval component uses the following fields:
```text
log_message
log_message_embedding
```
```log_message``` contains the ROS 2 message text, while ```log_message_embedding``` contains its corresponding vector representation.

## Atlas Search index

Create an Atlas Search index named ```search_index``` using the following configuration:

```json
{
  "mappings": {
    "dynamic": false,
    "fields": {
      "log_message": [
        {
          "type": "string"
        }
      ]
    }
  }
}
```

This index enables lexical retrieval over the `log_message` field using BM25.

## Atlas Vector Search index

Create an Atlas Vector Search index named ```vector_index``` using the following configuration:

```json
{
  "fields": [
    {
      "numDimensions": 1536,
      "path": "log_message_embedding",
      "similarity": "dotProduct",
      "type": "vector"
    }
  ]
}
```

The `numDimensions` value must match the dimensionality of the embeddings generated by the selected embedding model.

The configuration above corresponds to the OpenAI embedding model used in the experiments, which generates vectors with 1536 dimensions.

## Embedding generation

MongoDB Atlas Triggers are used to automatically generate vector embeddings when new ROS 2 messages are inserted into the collection.

The repository provides two example implementations for embedding generation:

- **OpenAI**, using the `text-embedding-ada-002` model employed in the experiments;
- **Hugging Face**, using `intfloat/multilingual-e5-large` as an alternative for users who do not want to use the OpenAI API.

These implementations are provided as examples and can be adapted to other embedding models or external embedding services. When using a different model, the corresponding embedding generation Function and API configuration must be updated accordingly, and the dimensionality of the generated embeddings must match the `numDimensions` configured in the MongoDB Atlas Vector Search index.

Only the embedding Function corresponding to the selected embedding model should be associated with the Database Trigger.

The generated embedding is stored in the `log_message_embedding` field.

### OpenAI

The OpenAI implementation uses the OpenAI Embeddings API with the `text-embedding-ada-002` model, which was used in the experiments.

The OpenAI API key must be stored securely as a MongoDB Atlas Secret. An Atlas Value linked to this Secret can be created with the name ```OPENAI_VALUE```

The Trigger Function retrieves the text from the `log_message` field, sends it to the OpenAI Embeddings API, and stores the resulting vector in the ```log_message_embedding``` field.

The complete OpenAI Trigger Function is available [here](https://github.com/laurafbec/agentic-rag-xar/blob/main/mongodb-atlas-vector-search/triggers/OpenAITrigger.js).

### Hugging Face

The repository also provides an alternative implementation based on the
Hugging Face Inference API. The provided configuration uses the ```intfloat/multilingual-e5-large``` model.

The Hugging Face API key must be stored securely as a MongoDB Atlas Secret. An Atlas Value linked to this Secret can be created with the name ```HUGGINGFACE_VALUE```.

The Trigger Function sends the text from ```log_message``` field to the Hugging Face Inference API, and stores the resulting embedding in ```log_message_embedding``` field.

The complete Hugging Face Trigger Function is available [here](https://github.com/laurafbec/agentic-rag-xar/blob/main/mongodb-atlas-vector-search/triggers/HuggingFaceTrigger.js).

The provided implementations can be adapted to other embedding models or services. When using a different model, the corresponding Trigger Function must be updated and the ```numDimensions``` value in the Atlas Vector Search
index must match the dimensionality of the generated embeddings.

## Trigger configuration

Create a MongoDB Atlas Database Trigger configured to execute whenever a new document is inserted into the target collection.

Use the following configuration:

```text
Trigger Type:    Database
Watch Against:   Collection
Cluster Name:    <CLUSTER_NAME>
Database:        <DATABASE_NAME>
Collection:      <COLLECTION_NAME>
Operation Type:  Insert Document
Full Document:   Enabled
Event Ordering:  Enabled
```

The Trigger must execute the Function corresponding to the selected embedding service.

The Function must use the same cluster, database, and collection configured for the application.

Replace ```<CLUSTER_NAME>, <DATABASE_NAME>, <COLLECTION_NAME>``` with the corresponding MongoDB Atlas values.

## Hybrid retrieval

The retrieval component combines two independent searches:

1. **Lexical search**, performed over ```log_message``` using MongoDB Atlas Search and BM25.
2. **Vector search**, performed over ```log_message_embedding``` using MongoDB Atlas Vector Search.

The rankings obtained from both retrieval methods are combined using **Reciprocal Rank Fusion (RRF)**.

The parameters controlling this retrieval process are defined in the application configuration.

## Verification

After completing the MongoDB Atlas configuration:

1. Insert a document containing a `log_message` field into the configured collection.
2. Verify that the document is correctly stored in MongoDB Atlas.
3. Verify that the Database Trigger is executed.
4. Confirm that the Trigger adds the `log_message_embedding` field to the document.
5. Verify that `search_index` is active.
6. Verify that `vector_index` is active.

A successfully processed document should contain both fields:

```json
{
  "log_message": "<ROS message>",
  "log_message_embedding": [...]
}
```

The MongoDB Atlas database is then ready to be used by the retrieval component.
